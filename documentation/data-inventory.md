# Data inventory and provenance

## Primary source

The flight-delay workflow uses the U.S. Bureau of Transportation Statistics (BTS)
On-Time Performance data for Southwest Airlines (`WN`). The current study window is
January through April 2026, and the prediction target is departure delay of at least
15 minutes for a flight with a preceding flight on the same aircraft tail.

Raw files are intentionally excluded from Git because they are large source data.
Place the four extracted files at:

```text
data/raw/T_ONTIME_REPORTING_YYYY-MM/T_ONTIME_REPORTING.csv
```

The required raw columns and local setup are documented in
[`data/raw/README.md`](../data/raw/README.md). Run `python -m src.validate_data`
before preprocessing.

## Reference data

`data/reference/airport_timezones.csv` maps airport codes to IANA time zones. It is
used to convert BTS local clock fields into UTC before aircraft sequences are linked.

## Generated outputs

The preprocessing and modeling notebooks write cleaned pair data, metrics, figures,
and reports under `data/processed/` and `reports/`. The dashboard artifact is
`dashboard/dashboard-data.js`; it is regenerated by the final cell of
`notebooks/07_scenario_simulation_and_demo.ipynb`.

## Provenance recording

For each downloaded raw file, record the BTS download date and SHA-256 checksum in
the project handoff or release notes. Checksums are not invented here because the
raw files are not present in this checkout. On PowerShell, use:

```powershell
Get-FileHash .\data\raw\T_ONTIME_REPORTING_YYYY-MM\T_ONTIME_REPORTING.csv -Algorithm SHA256
```
